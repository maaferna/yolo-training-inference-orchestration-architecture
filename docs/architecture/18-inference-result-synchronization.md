# Inference Result Synchronization Layer

> **Status**: System-level integration component  
> **Complexity**: High  
> **Portfolio Value**: ⭐⭐⭐⭐⭐ (Demonstrates system-level problem-solving)

---

## Executive Summary

The **Inference Result Synchronization Layer** is the system component responsible for ensuring that inference results generated by the FastAPI compute service are properly copied, organized, and made accessible to the Django web application for visualization and download.

This component solves a **critical multi-layer coordination challenge**:

- FastAPI generates results in its container filesystem (`/app/compute_service/outputs`)
- Django needs to access these results from its container (`/app/web_service/outputs`)
- These must be served publicly via HTTP (`/media/deep_learning_outputs/outputs`)
- All while maintaining consistency, preventing race conditions, and avoiding data corruption

**Result**: Users see inference results (images, metrics, CSVs, shapefiles) rendered in Django UI within 5-10 seconds of inference completion.

## Problem Statement

### The Multi-Layer Path Challenge

When a user requests inference through Django:

```
User submits request (Django)
    ↓
Django calls FastAPI API
    ↓
FastAPI generates results: /app/compute_service/outputs/run_20260614_123456/
    ↓
FastAPI returns output_storage_path in JSON response
    ↓
Django receives: "/app/compute_service/outputs/run_20260614_123456/"
    ↓
Problem: Django container cannot directly access this path!
    (Different mount configuration, different container namespace)
```

### Why Paths Don't Match

**Host Filesystem**:
```
/home/user/ml_projects/outputs/run_20260614_123456/
  ├── image_001_annotated.jpg
  ├── image_002_annotated.jpg
  ├── metrics.json
  ├── detections.csv
  └── shapefiles/
```

**FastAPI Container** (via bind mount):
```
/app/compute_service/outputs/run_20260614_123456/
  ├── image_001_annotated.jpg
  ├── image_002_annotated.jpg
  ├── metrics.json
  ├── detections.csv
  └── shapefiles/
```

**Django Container** (via shared volume):
```
/app/web_service/outputs/run_20260614_123456/
  ├── image_001_annotated.jpg
  ├── image_002_annotated.jpg
  ├── metrics.json
  ├── detections.csv
  └── shapefiles/
```

**Public Browser URL** (Django template):
```html
<img src="/media/deep_learning_outputs/outputs/run_20260614_123456/image_001_annotated.jpg">
```

**The Issue**: FastAPI returns a path that doesn't exist in Django's container!

## Architecture & Components

### Layer 1: Inference Trigger (Django)

**What Happens**:
1. User selects inference parameters (project, YOLO version, image directory)
2. Django constructs HTTP payload
3. Django sends POST request to FastAPI
4. Django **waits** for response (synchronous)

**Key Decision**: Synchronous HTTP in Phase 1 simplicity
- Alternative: Async job queue (deferred to Phase 2)
- Trade-off: Limited to 30-min timeout; fine for typical inferences

---

### Layer 2: Inference Execution (FastAPI)

**What Happens**:
```python
# Pseudocode
@app.post("/inference/yolo-high-res")
def inference_endpoint(request):
    # Step 1: Validate request
    validate_parameters(request)
    
    # Step 2: Find best model
    model = get_best_model(
        project=request.project,
        yolo_version=request.yolo_version,
        yolo_size=request.yolo_size
    )
    
    # Step 3: Execute inference (YOLO or SAHI)
    if request.use_sahi:
        results = sahi_inference(model, images_path)
    else:
        results = yolo_inference(model, images_path)
    
    # Step 4: Generate artifacts
    output_path = f"/app/compute_service/outputs/run_{timestamp}/"
    save_images(results, output_path)
    save_metrics(results, output_path)
    save_csv(results, output_path)
    save_shapefiles(results, output_path)
    
    # Step 5: Return metadata
    return {
        "output_storage_path": output_path,
        "run_slug": run_slug,
        "artifact_count": 45,
        "execution_time": 127.5
    }
```

**Output Artifacts Generated**:
- Annotated images (with bounding boxes)
- JSON metrics (precision, recall, mAP50, mAP75, F1)
- CSV detections (class, confidence, bbox coordinates)
- Shapefiles (for geospatial visualization)
- Metadata JSON (run timestamp, parameters, counts)

### Layer 3: Path Translation (Django)

**The Core Problem Solved**:

Django receives FastAPI response with path in **FastAPI container coordinates**, but needs to:
1. Translate to host filesystem path
2. Copy files to Docker volume (accessible by Django)
3. Translate to public URL (accessible by browser)
4. Store in database for future reference

**Path Translation Logic**:

```python
# Input from FastAPI (container coordinates)
fastapi_output_path = "/app/compute_service/outputs/run_001/"

# Step 1: Container → Host
# Docker bind mount config: /home/user/outputs ↔ /app/compute_service/outputs
# So: /app/compute_service/outputs/run_001 → /home/user/outputs/run_001
host_path = "/home/user/outputs/run_001/"

# Step 2: Host → Volume
# Copy from host (/home/user) to volume (/app/web_service)
# Docker compose manages this path
# After copy: /app/web_service/outputs/run_001
volume_path = "/app/web_service/outputs/run_001/"

# Step 3: Volume → Public URL
# Django static file serving config maps /app/web_service to /media/
# So: /app/web_service/outputs/run_001/image.jpg → /media/deep_learning_outputs/outputs/run_001/image.jpg
public_url = "/media/deep_learning_outputs/outputs/run_001/"
```

**Implementation** (Django view):

```python
def copy_inference_results(fastapi_response):
    """
    Synchronize inference results from FastAPI to Django volume
    """
    fastapi_path = fastapi_response['output_storage_path']
    run_slug = fastapi_response['run_slug']
    
    # Get configuration (from settings or environment)
    host_outputs_dir = settings.INFERENCE_HOST_PATH  # /home/user/outputs
    volume_outputs_dir = settings.INFERENCE_VOLUME_PATH  # /app/web_service/outputs
    media_url_prefix = settings.MEDIA_DEEP_LEARNING_PREFIX  # /media/deep_learning_outputs
    
    # Map: FastAPI path (container) → Host path
    relative_run_dir = os.path.basename(fastapi_path)
    host_source = os.path.join(host_outputs_dir, relative_run_dir)
    
    # Map: Host → Volume (shared storage)
    volume_destination = os.path.join(volume_outputs_dir, relative_run_dir)
    
    # Step 1: Wait for FastAPI to finish writing
    wait_for_path(host_source, timeout=300)  # 5 minutes
    
    # Step 2: Verify required files exist
    required_files = ['metrics.json', 'detections.csv']
    for filename in required_files:
        filepath = os.path.join(host_source, filename)
        assert os.path.exists(filepath), f"Missing: {filepath}"
    
    # Step 3: Copy files to volume
    shutil.copytree(host_source, volume_destination, dirs_exist_ok=True)
    
    # Step 4: Generate public URLs
    image_url = f"{media_url_prefix}/outputs/{relative_run_dir}/image_annotated.jpg"
    metrics_url = f"{media_url_prefix}/outputs/{relative_run_dir}/metrics.json"
    csv_url = f"{media_url_prefix}/outputs/{relative_run_dir}/detections.csv"
    
    return {
        'volume_path': volume_destination,
        'image_url': image_url,
        'metrics_url': metrics_url,
        'csv_url': csv_url
    }
```

## Technical Challenges & Solutions

### Challenge 1: Path Coordinate System Mismatch

**Problem**: 
- FastAPI returns path in its container coordinate system
- Django cannot directly access that path (different mount)
- Manual path translation required

**Solution - Path Translation Layer**:

```python
class PathTranslator:
    """
    Maps between 4 coordinate systems:
    1. Container (FastAPI): /app/compute_service/outputs/...
    2. Host: /home/user/outputs/...
    3. Volume (Django): /app/web_service/outputs/...
    4. Public URL: /media/deep_learning_outputs/...
    """
    
    def __init__(self, config):
        self.fastapi_container_path = "/app/compute_service/outputs"
        self.host_path = config['INFERENCE_HOST_PATH']  # /home/user/outputs
        self.volume_path = config['INFERENCE_VOLUME_PATH']  # /app/web_service/outputs
        self.media_url = config['MEDIA_URL_PREFIX']  # /media/deep_learning_outputs
    
    def container_to_host(self, container_path):
        """FastAPI container path → Host filesystem path"""
        # Remove container prefix, add host prefix
        relative = container_path.replace(
            self.fastapi_container_path, ""
        ).lstrip('/')
        return os.path.join(self.host_path, relative)
    
    def host_to_volume(self, host_path):
        """Host filesystem → Django volume"""
        relative = os.path.relpath(host_path, self.host_path)
        return os.path.join(self.volume_path, relative)
    
    def volume_to_url(self, volume_path):
        """Django volume → Public URL"""
        relative = os.path.relpath(volume_path, self.volume_path)
        return f"{self.media_url}/outputs/{relative}"
    
    def fastapi_response_to_urls(self, fastapi_response):
        """End-to-end translation"""
        fastapi_path = fastapi_response['output_storage_path']
        host_path = self.container_to_host(fastapi_path)
        volume_path = self.host_to_volume(host_path)
        
        return {
            'host_path': host_path,
            'volume_path': volume_path,
            'image_url': self.volume_to_url(volume_path) + '/image_annotated.jpg',
            'metrics_url': self.volume_to_url(volume_path) + '/metrics.json',
            'csv_url': self.volume_to_url(volume_path) + '/detections.csv'
        }
```

### Challenge 2: Race Conditions in File Synchronization

**Problem**:
- Django tries to copy files while FastAPI is still writing
- Results in incomplete or corrupted files
- Metadata in database references files that don't exist yet

**Solution - Wait-for-Completion Pattern**:

```python
def wait_for_path(path, timeout=300, check_interval=0.5):
    """
    Wait for directory to be stable (FastAPI finished writing)
    
    Strategy:
    1. Check directory exists
    2. Get file count
    3. Wait 5 seconds
    4. Recheck file count
    5. If count unchanged, directory is stable
    6. Return True if stable within timeout
    """
    start_time = time.time()
    previous_file_count = -1
    stable_count = 0
    required_stable_checks = 3  # Must be stable for 3 checks
    
    while time.time() - start_time < timeout:
        if not os.path.exists(path):
            time.sleep(check_interval)
            continue
        
        try:
            # Count files
            files = os.listdir(path)
            current_count = len(files)
            
            # Check for required files
            required = ['metrics.json', 'detections.csv']
            has_required = all(f in files for f in required)
            
            if not has_required:
                stable_count = 0
                previous_file_count = current_count
                time.sleep(check_interval)
                continue
            
            # Check if count is stable
            if current_count == previous_file_count:
                stable_count += 1
                if stable_count >= required_stable_checks:
                    return True  # Directory is stable!
            else:
                stable_count = 0  # Reset counter
            
            previous_file_count = current_count
            time.sleep(check_interval)
            
        except OSError:
            time.sleep(check_interval)
            continue
    
    # Timeout occurred
    raise TimeoutError(
        f"Directory {path} not stable after {timeout} seconds"
    )
```

**Timeline of File Synchronization**:

```
FastAPI Writing Timeline:
─────────────────────────────────────────────────────────────────

T=0s     FastAPI starts writing output files
         │
T=10s    Writes: image_001.jpg, image_002.jpg (in progress)
         │
T=30s    Writes: metrics.json (PARTIALLY - still writing)
         │
T=45s    Writes: detections.csv (PARTIALLY)
         │
T=60s    ✓ All files complete, directory is stable
         │
         ↓ Django wait_for_path() detects stability
         │
         ↓ Django begins copy operation
         │
         ✓ Results accessible in /app/web_service/

Without wait_for_path(): Copy would start at T=30s → corrupt metrics.json
With wait_for_path(): Copy waits until T=60s → all files complete
```

### Challenge 3: Model Discovery Failures

**Problem**:
- FastAPI can't find trained model (path mismatch)
- Returns HTTP 404 to Django
- Django renders error, but user doesn't know why

**Solution - Detailed Error Responses**:

```python

@app.post("/inference/high-resolution")
def inference_endpoint(request: InferenceRequest):
    try:
        # Attempt to find model
        model_path = get_best_model(
            project=request.project,
            yolo_version=request.yolo_version,

            "status": "error",
            "error_code": 422,
            "error_message": str(e),
            "error_type": type(e).__name__,
```

### Challenge 4: Metadata Consistency

**Problem**:
- Database stores paths from different layers (container, host, volume, URL)
- Confusion about which path is which
- Potential to serve wrong URLs

**Solution - Store Only Volume/URL Paths**:

```python
class InferenceRun(models.Model):
```

## Lessons Learned

### 1. Docker Path Complexity is Underestimated

**Lesson**: Multi-container systems create coordinate system complications

**Application**: 
- Always document how each container sees filesystem paths
- Create explicit path mapping configuration (not hardcoded)
- Test path translation with real Docker setup, not just local development

---

### 2. File Synchronization Needs Explicit Waiting

**Lesson**: Copying while source is being written causes data corruption

**Application**:
- Always wait for "stability signal" (file count unchanged over time)
- Never assume instantaneous file availability
- Implement timeout-based polling rather than single-check

---

### 3. Error Messages Should Include Context

**Lesson**: "Model not found" is useless; "Model not found, try one of [...]" is helpful

**Application**:
- Always provide available options when selection fails
- Include search parameters in error message
- Suggest next steps or fixes

---

### 4. Database Should Store Final-Layer Paths

**Lesson**: Storing intermediate paths creates confusion and errors

**Application**:
- Never store container-layer paths in database
- Always convert to final accessible layer before persistence
- Validate paths match expected patterns during save

---

### 5. Synchronous Request-Response Limits Scalability

**Lesson**: 30-minute HTTP timeout insufficient for long jobs

**Application**:
- Monitor job duration distribution
- When median job > 15 minutes, plan Phase 2 (async queue)
- Track "queue wait time" as scaling trigger metric

### Risk 1: Corrupted Files During Copy

**Mitigation**:
- ✅ Use wait_for_path() before copying
- ✅ Verify file counts after copy
- ✅ Implement checksums for critical files
- ✅ Roll back on copy failure

### Risk 2: Path Translation Misconfiguration

**Mitigation**:
- ✅ Centralize path configuration in settings
- ✅ Add validation in __init__() (verify paths exist)
- ✅ Test translation with real Docker paths
- ✅ Log all path translations for debugging

### Risk 3: Concurrent Inference Job Conflicts

**Mitigation**:
- ✅ Use unique run_slug per job (timestamp + random)
- ✅ Separate output directories per job
- ✅ Lock best_model_ref.json during updates
- ✅ Consider job queue in Phase 2

### Risk 4: Database-Filesystem Mismatch

**Mitigation**:
- ✅ Always store FINAL paths (volume/URL)
- ✅ Validate paths during ORM save()
- ✅ Implement periodic consistency check
- ✅ Log mismatches for investigation
